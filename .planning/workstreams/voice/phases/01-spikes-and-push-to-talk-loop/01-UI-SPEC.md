# Phase 1 - UI Design Contract

> Visual and interaction contract for the Blip voice window. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: CONTEXT.md D-01..D-04 (locked), ROADMAP Phase 1 success criteria, CLAUDE.md stack. Items marked (default) are researcher choices, not user decisions.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Vite vanilla TypeScript template, plain CSS in one `styles.css`, CSS custom properties for tokens) |
| Preset | not applicable |
| Component library | none (semantic HTML only) |
| Icon library | none. Status uses text labels plus inline SVG shapes drawn in the markup (no dependency). |
| Font | `system-ui, "Segoe UI", sans-serif` (default; Windows demo machines) |

---

## Window and Layout

- Separate popup window, opened at startup, always on top (D-01). Opened by `chrome.exe --app=http://localhost:8787` in the dedicated profile (the Phase 1 spike can swap to a narrower popup).
- Default size 420 x 720 px, docked to the right edge of the screen beside the form window (default). Min width 360 px. Layout is a single column and must hold from 360 to 560 px wide with no horizontal scroll.
- Vertical order (DOM order = visual order = focus order):
  1. `<header>`: product name "Blip" (h1) and connection indicator.
  2. `<section id="status">`: state badge (listening / thinking / speaking / idle) and the push-to-talk hint.
  3. `<section id="banner-slot">`: reserved for the Phase 2 BLOCKED banner. Always in the DOM, 0 height when empty, `role="alert"` is NOT set in Phase 1. It sits above the transcript so it is never pushed off-screen. Reserved height when used: 96 px.
  4. `<section id="caption">`: live caption of the current utterance (D-04).
  5. `<main>` / `<section id="log">`: finished exchange log, scrolls; newest at the bottom, auto-scroll unless the user has scrolled up.
  6. `<form id="typed">`: typed-input box and Send button, pinned at the bottom (sticky).
- Focus order: connection (non-focusable) -> log (tabindex 0, scrollable region) -> typed input -> Send. On load, focus goes to the typed input. Pressing Escape in the input clears it.
- Start gate: on first load show a single button "Press Space to start Blip" (needed for speechSynthesis user activation per CLAUDE.md). It is the only focusable element until activated, then it is removed and focus moves to the typed input.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between badge icon and text |
| sm | 8px | Between log entry lines, input padding |
| md | 16px | Section padding, gap between sections |
| lg | 24px | Gap between log exchanges |
| xl | 32px | Start-gate button padding |
| 2xl | 48px | Minimum touch/click height of Send and typed input |
| 3xl | 64px | Not used in Phase 1 |

Exceptions: banner slot reserved height 96 px (multiple of 4, equals 6 x md; named token `banner`). The 3 px focus-ring width and 2 px offset are outline properties, not layout spacing, and are exempt from the grid.

Focal point: the 28 px live caption is the primary visual anchor while the user is speaking. The status badge is secondary and wins only when no caption is showing (idle, thinking, speaking, offline).

Planner notes (from the checker): (1) The window is "always on top" only if a mechanism exists. `--app` alone does not do it, so plan the Win32 topmost call (or a spike) with "docked beside the form" as the fallback. (2) The "Press Space to start Blip" gate must listen only in the window's own keydown handler, never from the global uiohook Right Ctrl + Space hold.

## Typography

Large for sighted judges reading from a distance and for low-vision users. Exactly 4 sizes, 2 weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (log text, input) | 18px | 400 | 1.5 |
| Label (speaker tags "You" / "Blip", hints, connection) | 14px | 600 | 1.5 |
| Heading (h1 "Blip", status badge text) | 24px | 600 | 1.2 |
| Display (live caption) | 28px | 400 | 1.2 |

## Color

Dark high-contrast theme (default). All text/background pairs at least 7:1 (WCAG AAA); non-text indicators at least 3:1.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F14` | Window background, log area |
| Secondary (30%) | `#1B2430` | Status section, caption panel, typed-input bar, log entry cards |
| Accent (10%) | `#FFD60A` | See reserved list below |
| Destructive | `#FF6B6B` | Blocked/error indications only (connection lost, mic error); also the Phase 2 BLOCKED banner |
| Text primary | `#F5F7FA` | All body text (on `#0B0F14`: about 17:1) |
| Text muted | `#B8C2CC` | Hints and timestamps (on `#1B2430`: about 8:1) |

Accent reserved for: (1) focus ring (3 px outline, 2 px offset) on every focusable element, (2) the listening state badge border and fill, (3) the Send button background (text `#0B0F14`), (4) the "Blip" speaker tag in the log. Never used for body text or generic links.

Status never relies on color alone: each state has a distinct text label and a distinct SVG shape (see Interaction).

## Interaction Contract

**Status states** (one visible at a time, in `#status`, text 24px/600 plus shape):

| State | Label text | Shape | Trigger |
|-------|-----------|-------|---------|
| idle | "Ready" | hollow circle | default; hint "Hold Right Ctrl + Space to talk" |
| listening | "Listening" | filled circle with pulsing ring (no pulse if `prefers-reduced-motion`) | PTT keydown (earcon plays) |
| thinking | "Thinking" | three dots | after release until reply; "one moment" spoken once if over 1.5 s |
| speaking | "Speaking" | speaker/bars shape | Blip TTS playing; hint "Say stop or hold Right Ctrl + Space to interrupt" |
| offline | "Not connected" | X shape, destructive color | socket closed; auto-retry every 2 s |

**Live caption (D-04):** `<p id="caption" aria-live="off">` shows interim results in muted text, final text in primary. Cleared 1 s after the utterance is committed to the log. Placeholder when empty and idle: "Your words appear here." Caption is NOT in a live region (it changes too fast and would spam NVDA).

**Log (D-04):** `<ol role="log" aria-live="polite" aria-relevant="additions" aria-label="Conversation">`. Each exchange is one `<li>` with two lines: "You" tag + utterance, then "Blip" tag + reply. Only the finished reply is appended (single insertion, so NVDA announces once). Typed and spoken inputs render identically; typed ones carry the tag "You (typed)". Keep the last 50 exchanges.

**Typed input:** `<label for="typed-input">Type a command</label>` (visible label), `<input type="text" autocomplete="off">`, Enter or Send submits as `{type:"utterance", source:"typed"}` and returns the same reply as speech. Input clears on submit and keeps focus. Empty submit does nothing silently (no error).

**Barge-in (D-03):** while speaking, a PTT press or recognized "stop" cuts TTS immediately, status goes to listening, and the log entry for the interrupted reply is marked "(interrupted)". The UI never decides confirm-phrase matches.

**Earcons:** listening on keydown, thinking while waiting, blocked (Phase 2 use). Short, under 300 ms, volume lower than speech.

**Motion:** only the listening pulse; disabled under `prefers-reduced-motion`.

## Accessibility Contract

- Real semantic HTML: header, main, section with `aria-labelledby`, ol, form, label, button. No div buttons.
- Language `lang="en"`; page title "Blip".
- Status container `role="status"` with `aria-live="polite"`; announce only state changes, and mute announcements in the status container when screen-reader mode (Phase 4) is on to avoid double speech.
- Connection indicator has text, not color alone.
- Minimum target size 48 px height; Tab only (no custom shortcuts beyond PTT).
- Zoom to 200% must not clip content.
- The NVDA live-region behavior with the form tab focused is a Phase 1 spike; this contract must be revised if the spike shows the log is not announced.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Send Command" (typed input); start gate: "Press Space to start Blip" |
| Empty state heading | "Nothing yet" |
| Empty state body | "Hold Right Ctrl + Space and say what you want, or type it below. Try: what's here." |
| Error state (mic) | "I can't hear the microphone. Allow microphone access for this window, or type your command below." |
| Error state (connection) | "Not connected to the Blip server. Retrying. You can keep typing once it reconnects." |
| Error state (speech failed) | "I didn't catch that. Hold the keys and try again, or type it." |
| Destructive confirmation | none in Phase 1 (no destructive actions). Phase 2 banner text format reserved: "BLOCKED - say '{phrase}'". |
