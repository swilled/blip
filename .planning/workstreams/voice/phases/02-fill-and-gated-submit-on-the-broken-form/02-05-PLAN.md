<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| voice socket utterance -> reducer | Only role=voice utterance text may confirm (enforced by the runner in plan 06; reducer matches text only) |
| Blip speech -> mic | Blip's own prompt may be re-heard as an utterance |
| reducer -> gate (via runner) | armConfirm / redeem are requests; the gate decides |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-21 | Tampering | bare yes / near-phrase confirms submit | mitigate | Exact token match only, refusal is the default branch, 25-row table, 500-seed invariant |
| T-02-22 | Spoofing | Blip's own prompt confirms itself | mitigate | confirmWindowOpen requires no outstanding speak and 1000 ms after last done; boundary tests at 999/1000 ms |
| T-02-23 | Elevation | arming without the user hearing the read-back | mitigate | Arm only on uninterrupted speak.done of the correlated read-back speakId with unchanged digest; interrupted/filler/wrong-id tests |
| T-02-24 | Elevation | model approves via parseIntent | mitigate | No parseIntent emission in reading-back/awaiting-confirm/executing; asserted by table test and invariant 2 |
| T-02-25 | Tampering | page text becomes the phrase | mitigate | Phrase only from confirm.armed event; reducer never reads phrase from ctx.form |
| T-02-26 | Tampering | double redeem / replay | mitigate | mode executing ignores utterances; invariant 3; grant single-use is also the gate's job |
| T-02-27 | Info disclosure | sensitive values in read-back | mitigate | readBackText uses hasValue only (plan 02 test); submit.test re-checks with a marker sensitive field |
