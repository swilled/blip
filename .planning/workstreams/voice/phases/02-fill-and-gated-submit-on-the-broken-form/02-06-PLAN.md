The returned handlers are utterance, "speak.done", "page.changed" and control only; the closure holds one DialogueState (from initialState()) so restarting the process is the session reset (D-09). All three handlers push their work onto ONE promise queue so state stays consistent (a failed job must not block the next).

utterance handler: ignore unless ctx.role === "voice" and message.type === "utterance" (matching happens only on voice-socket utterances). Set session.busy and pushState; best-effort ensure a fresh snapshot (snapshot.request reason "user" when session.model is null or stale; store the returned Snapshot.tabId in the closure; session.applySnapshot); treat the form as null when session.extensionConnected is false. Send a transcript frame {utteranceId, heardAs: text, routedTo} where routedTo is "model" iff the reducer produced a parseIntent effect, else "grammar". Reduce with ctx {form: session.model, now: now()}, then run effects in order via dispatch.

dispatch(event) is one function that reduces and then applies effects; follow-up events produced by effect execution (act.result, confirm.armed, confirm.refused, confirm.cleared, gated.result, form.changed) call dispatch directly (not re-enqueued) to avoid deadlock. After each dispatch set session.dialogue = dialogueStateName(state.mode), session.focusFieldId = state.currentFieldId ?? undefined, session.busy false, and call hub.pushState().

Effect execution: speak -> export a helper sendSpeakEffect(hub, effect) that THROWS (and sends nothing) when effect.speakId is missing or empty, with no newId() fallback anywhere, then hub.send("voice","speak",{speakId: e.speakId, text, category, interrupt: false}) and update session.lastSpoken for non-filler categories; earcon -> hub.send earcon; cancelSpeech -> hub.send speak {speakId: e.speakId (reducer-minted and tracked), text "Stopped.", interrupt: true}; parseIntent -> opts.parseIntent when given, else dispatch {type: "intent.reply", text: "I didn't understand that."} so the reducer speaks it through speakEffect; fill/select/focus -> hub.request("extension","act.request",...) with a built ActRequest (actId newId(), tabId from the last snapshot, snapshotVersion from session.model, action {op fill|select|focus}, expectedKind "fill" for fill and focus and "select" for select unless the fake extension source shows otherwise) and NEVER a gate field; call opts.onActRequest(req) before sending; map the ActResult (or a HubRequestError) to an act.result event with ok false and error "exception" on failure; the runner has no code path that builds a click op (the helper's op type is the union fill|select|focus). refreshForm -> snapshot.request reason "post-act", applySnapshot, then dispatch form.changed. armConfirm -> gate.arm; ok -> hub.send("voice","confirm.armed",{grantId, phrase, kind, actionLabel (the action's label from the model, sanitized), expiresAt}) then dispatch confirm.armed, and schedule an expiry timer (unref'd) whose callback enqueues a job on the SAME promise queue (never dispatches directly from the timer) that calls gate.clear(grantId,"expired"), sends confirm.cleared and dispatches confirm.cleared {expired}; not ok -> dispatch confirm.refused. clearConfirm -> cancel the timer, gate.clear, hub.send confirm.cleared. redeem -> cancel the timer, await gate.redeem inside try/catch; if it rejects or throws, dispatch gated.result {ok: false, reason: "gate-error"} so the reducer never stays stuck in executing; otherwise dispatch gated.result with the outcome; always send confirm.cleared with reason "cancelled" when the stub refuses (so the banner clears) and "executed" only on ok:true.

speak.done handler: dispatch {type:"speak.done", done: payload} (this replaces core's no-op; reducer owns the GATE-08 window until core wires its own). control handler: ignore unless ctx.role === "voice"; for cmd stop or repeat dispatch {type: "control", cmd}; for reconnect-browser send the same not-implemented error frame core's default sends (replyTo the message id). page.changed handler: set session.stale = true; when the reducer state is awaiting-confirm, gate.clear + send confirm.cleared + dispatch confirm.cleared {page-changed}; when reading-back, refresh the snapshot then dispatch form.changed. Never log utterance text, labels or values (use no console calls; if a log is needed use the existing apps/server/src/log.ts with fixed messages only).
