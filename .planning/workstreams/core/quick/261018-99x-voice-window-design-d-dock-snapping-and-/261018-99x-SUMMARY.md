# Summary: Voice window Design D, dock snapping and smooth motion

- `apps/server/src/voice/window-dock.ts`: pure layout math (tested) and a koffi user32/dwmapi driver.
  It finds the exact-titled "Blip" window and the topmost chrome/msedge/brave window, compensates for
  invisible DWM borders, and tweens both over 240 ms. Drag folds Blip into a 340x72 puck that follows
  the cursor, reports the zone, and snaps on release. Esc or a 30 s limit returns it to the last dock.
- `ptt-sidecar.ts`: when a window handler is wired, accepts only `{dock}` / `{drag}` frames up to 64 chars,
  greets new connections with `{docked}` / `{dockAvailable:false}`, and broadcasts window events.
  Any other inbound frame still closes with 1008. `ptt-wire.ts` wires it on win32 only.
- Voice window: grip, wordmark and dock picker header; strip/puck layout set from JS `data-layout` with view
  transitions; "Locked · say “phrase”" banner; crossfading status shapes; animated label, banner, log,
  caption, popovers, gate exit and hold button. `prefers-reduced-motion` turns motion off.
- Verified: `npx vitest run apps/voice apps/server/src/voice` (183 pass), `tsc` clean, voice build OK,
  Win32 bindings load and enumerate windows. Not verified: a live drag and snap with real windows.
- Deviation: implemented inline instead of spawning planner/executor subagents. Full context was in hand.
