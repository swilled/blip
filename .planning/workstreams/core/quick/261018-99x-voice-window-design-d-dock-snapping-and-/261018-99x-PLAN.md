# Voice window Design D: dock snapping and smooth motion

Make the Blip voice window match direction D from the "Blip Design Directions" canvas
(D-Right, D-Left, D-Strip, D-Docks) and add its drag-to-dock behavior.

## Task 1: Win32 docking on the server

- files: apps/server/src/voice/window-dock.ts, apps/server/src/voice/window-dock.test.ts,
  apps/server/src/voice/ptt-sidecar.ts, apps/server/src/voice/ptt-sidecar.test.ts, dev/mock-server/src/ptt-wire.ts
- action: pure layout math (dock rects, drop zone from cursor, eased tween) plus a koffi user32/dwmapi
  driver that moves the exact-titled "Blip" app window to the left or right edge (browser window resized
  into the remaining space) or to a top-center strip (browser fills the work area). Drag start folds the
  window into a puck that follows the cursor and reports the drop zone; drag end snaps to it. The loopback
  sidecar accepts only strictly shaped `{dock}` / `{drag}` messages when a window handler is wired; it
  still closes the socket on anything else.
- verify: `npx vitest run apps/server/src/voice`
- done: tests pass; sidecar still rejects foreign origins and unknown messages.

## Task 2: Design D voice window with motion

- files: apps/voice/index.html, apps/voice/src/styles.css, apps/voice/src/main.ts, apps/voice/src/ui-log.ts,
  apps/voice/src/banner.ts, apps/voice/src/banner.test.ts, apps/voice/src/dock-client.ts, apps/voice/src/dock-client.test.ts
- action: header with grip and dock button (left, right, top strip options), D sidebar spacing, strip layout
  driven by a JS `data-layout` attribute with view transitions, "Locked · say …" pill, crossfading status
  shapes, animated label, banner, log, caption, sheets, gate exit and hold button. Reduced motion respected.
- verify: `npx vitest run apps/voice` and `npx tsc --noEmit -p apps/voice`
- done: tests and typecheck pass.
