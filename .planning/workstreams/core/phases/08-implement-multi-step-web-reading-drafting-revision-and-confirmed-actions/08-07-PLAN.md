The verification gap is specifically the `dialogueRunner: true` handler composition used by the demo. `server.ts` starts with core defaults, then overlays `createDialogueHandlers`; that runner owns reducer confirmation state and does not pass the original task redemption source to the Phase 8 gate. The Phase 8 router is already in `turn.ts`, and `createVoiceGateAdapter` already forwards source and IDs to the deterministic gate.

The Hub's role slot replacement is session-sensitive: `bind` installs the new slot before it closes the prior connection, and `onClose` clears a role only if the closing connection still owns that slot. A current voice disconnect sets `session.voiceConnected = false`; a replacement binds with `session.voiceConnected = true` while it is already true. In `Session`, either the false transition or repeated true assignment clears the active page task and its associated grant. The integration test must prove both current-voice disconnect/reconnect and direct voice replacement leave a saved old redeem unable to dispatch, without letting the replaced socket's late close clear its successor.

For settings, explicitly send `settings` with `outputMode: "screen-reader"` while a Phase 8 task grant is pending (the initial test session is `agent-voice`) and assert that grant invalidation occurs before a later redeem attempt. The Hub may fall back to agent voice when screen-reader completion is unavailable; the assertion is about invalidation on the settings event, not hardware output availability.

Keep normal form utterances and non-task confirmations on the existing DialogueRunner behavior. Route only recognized Phase 8 task commands and a pending task-bound grant to core. Reuse core's existing task/gate and fresh-result checks; do not make the reducer, page text, or provider an authority for actions. The handler composition must also route task lifecycle events (`speak.done`, interruption, stop/repeat/cancel, `page.changed`/tab changes, and settings) so grants cannot remain redeemable in runner mode.

Phase 8 has no shared requirement IDs. Keep the existing `send this email` phrase and protocol source field unchanged and local pending written voice-owner review. Do not edit `apps/voice`, `packages/dialogue`, shared protocol/policy, or Phase 7 link eligibility. No AGY CLI, account, private content, or external page is needed; tests must inject fakes and use synthetic local state only.
