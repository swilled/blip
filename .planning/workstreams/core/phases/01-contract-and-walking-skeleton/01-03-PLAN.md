<objective>
Phase goal (ROADMAP, Phase 1): Both developers build against one frozen contract, and the whole loop (typed utterance -> server -> extension snapshot -> spoken reply) runs on one machine with no Chrome, no voice UI and no Claude.

This plan delivers the fixtures voice needs at M0 and the baseline form model (PAGE-02), then gates the protocol freeze. It leads with a tracer on one path (the booking snapshot -> pure builder -> golden FormModel -> inside a `snapshot.result` frame), expands to the broken and result fixtures and the builder's edge cases, then stops at a blocking-human decision before the one-way freeze stamp.

Purpose: voice's reducer tests start from `booking.formmodel.json` the moment M0 lands; core's fake extension (plan 01-05) serves these snapshots. Generating the golden from the builder (not a second author's hand-written copy) removes the drift the golden test exists to catch.

Output: four snapshot fixtures plus one golden FormModel, the pure builder with unit tests (<100 ms on every fixture), a browser-safety test for the protocol package, the lock file and test that make D-17 mechanical, and a documented M0 decision.

Roadmap success criteria served: 3 (baseline form model under 100 ms, checked by unit tests) and 1 (M0 fixtures, docs and sign-off). Locked decisions: D-08, D-09, D-10, D-11, D-12, D-13, D-17.
