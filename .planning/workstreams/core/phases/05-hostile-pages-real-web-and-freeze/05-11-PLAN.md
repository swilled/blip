# Plan 05-11: Local Voice Window, Warning Speech, and Hackathon Demo Freeze

## User decision and scope

The core owner stated that this hackathon has no public-form URL and asked Core to test the project itself. Do not invent a team-owned/public target. Replace only Phase 5's I3 acceptance target with the repository's self-hosted synthetic survey form, and leave voice-owned `DEMO-03` (a public form) explicitly deferred. The demo remains local and uses fixed fictional data. This is a recorded scope change, not evidence that a public form was tested.

## Tasks

1. Add a small first-party voice window at `apps/voice/public` using the existing role=voice protocol. It must support typed utterances, browser push-to-talk where available, safe fixed warning speech for accepted GATE-07 state, and tracked server speech completion. A pending warning holds user input until its speech finishes. It must never display or speak page instruction prose.
2. Serve the voice window from the loopback server and launch it as an app window in the dedicated demo profile. Readiness must require the extension and voice role to connect. Keep server/extension loopback boundaries intact.
3. Add a deterministic synthetic survey form at a stable loopback origin/path with only fictional values and a local submit sink. Run a real-browser workflow against it. Under Claude mode, record the exact structural identity and prewarm a validated repair in a demo-only cache. The fake-brain demo must still launch and exercise the safety flow offline.
4. Update Phase 5 requirements, roadmap, state, verification, and summary from observed evidence. Close only GATE-07, PROT-03, local synthetic I3, and Freeze when each has direct evidence. Keep the public-form DEMO-03 deferred and visible.

## Safety and limits

- Never use a public form or real user data.
- The warning text is a fixed client-owned sentence based only on the warning boolean; raw page prose remains absent from the voice protocol and UI.
- The client reports `speak.done` only for the currently tracked server `speakId`, and only after speech ends. Unsupported/failed speech is reported as interrupted so a gated action cannot arm.
- Keep browser launch/cleanup scoped to the dedicated profile and child process; do not close the user's ordinary Edge/Chrome session.
- Do not create or move `demo-safe` until the complete revised local acceptance and fake fallback both pass.

## Verification

- Unit tests for voice frame validation, warning deduplication/input hold, and tracked completion behavior.
- `npm run typecheck` and `npm test`.
- Dedicated Edge E2E: accepted hostile warning is spoken before a queued utterance; read-back completion uses the matching `speakId`; gated submit still refuses without the exact confirmation; zero unauthorized submit effects.
- Dedicated Edge smoke: one command serves the survey and opens the voice app in the dedicated profile, with both extension and voice connections observed.
- Bounded real-Claude local survey run (synthetic input only) verifies a label patch and reload from the demo-only cache. No public target, credentials, or cache outside `.chrome-profile/demo-repair-cache` is inspected.
- Run the documented fake-brain fallback through the same local survey and submit gate.
