<objective>
Phase goal (ROADMAP, Phase 2): On a real page in Chrome, Blip reads the form's controls and fills them the way a person would, and only ever reports the value the page actually holds.

This plan builds the write side and the liveness of the real extension: fills that make React and Vue validation react and never send Enter (ACT-01), selects, radios and checkboxes (ACT-02), a visible highlight for sighted observers (ACT-03), read-back of the real DOM value after every write (ACT-04), refusal of every gated click (D-06, PAGE-03 enforcement), and page-change detection so the server's model follows the page within about a second (PAGE-05). It leads with the D-04 confirmation on a real browser, a text fill into a real React-controlled form, then completes every op, the overlay and frame/shadow routing, then adds the mutation observer, navigation signals and the debounced notifier.

Purpose: plan 02-06 verifies the whole slice with a matrix and a manual checklist; the server act path from plan 02-04 is the only caller.

Output: `act.ts`, `fill.ts`, `focus.ts`, `overlay.ts`, `observer.ts`, `acts.ts`, `changes.ts`, `navigation.ts` and real-browser tests that prove the success criteria on the test pages.

Roadmap success criteria served: 3 (React-safe fills, no Enter, highlight, read-back, truncation reported), 4 (model within about 1 s of a page change; keepalive is plan 02-01), 2 (extension refuses gated clicks). Locked decisions: D-02, D-03, D-04, D-06, D-07, D-13, D-14, D-15, D-16, D-17, D-18, D-19. Amendments: A-02 (maxlength clamp), A-03 (synthetic focus and blur when the page is not OS-focused).

D-04 guard: this task order puts the React-controlled fill confirmation first. If the fill does not move React's state on a real browser even though the recipe is implemented exactly as specified, STOP and return a checkpoint to the user with the evidence. Escalating to a CDP input path is the user's decision and is not part of this plan; do not build it.
</objective>
