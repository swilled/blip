<objective>
Phase goal (ROADMAP, Phase 2): On a real page in Chrome, Blip reads the form's controls and fills them the way a person would, and only ever reports the value the page actually holds.

This plan is the foundation of the extension lane. It gates every new dependency behind one blocking-human checkpoint, creates the `@blip/extension` workspace with a plain esbuild build and a hand-written manifest (D-08, D-09), and leads with a tracer that proves the riskiest platform assumptions on a real browser before any DOM logic is written: the unpacked build gets the pinned extension id, its MV3 service worker opens `ws://127.0.0.1` with the pinned Origin, says hello as `extension`, and is bound by a production-mode server (the open item from Phase 1). It then hardens the connection (pure backoff and dead-peer policy, alarm wake-up, idempotent content script, re-injection on install, typed failure replies) and proves reconnect after a server restart.

Purpose: PAGE-05 needs the socket to survive an idle service worker (roadmap criterion 4, first half), and every later plan needs a way to run the real extension under an automated test. The harness created here (`createRig`) is what plans 02-03, 02-05 and 02-06 use to prove their slices on a real browser.

Output: `npm run ext:build`, `npm run ext:smoke`, a green typecheck and test run, and an extension that connects, reconnects and answers nothing falsely.

Roadmap success criteria served: 4 (keepalive and reconnect half). Locked decisions implemented here: D-01 (no debugger; costly reversibility is recorded on plan 02-03 where the engine is built), D-08, D-09, D-10 (build and watch scripts, `.chrome-profile/` ignored), D-12. Amendments: A-07 (jsdom 29.1.1, @types/chrome, no Playwright), A-08 (Edge fallback via `BLIP_BROWSER` and `scripts/browser.ts`).

6. `socket.ts` (D-12): module state for one WebSocket. `ensureConnected()` is idempotent: it returns when the policy blocks, or when a socket is OPEN or CONNECTING; otherwise it creates `new WebSocket(url)` where url is the `__BLIP_WS_URL__` define when present (guard with a typeof check) and otherwise `ws://` + `LOOPBACK_HOST` + `:` + `DEFAULT_PORT` + `WS_PATH`. On close or error: clear timers, clear welcomed, schedule `ensureConnected` after `nextDelay()`. Export `send(type, payload, opts)` (builds the frame with `buildFrame` and returns false when the socket is not OPEN; the open handler sends hello itself, and every other caller checks `isWelcomed()` first), `setInboundHandler`, `onWelcome`, `isWelcomed`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry -> repo | Third-party packages enter the build; flagged only by a recency heuristic |
| web page -> loopback WebSocket | Any website can open ws://127.0.0.1; the hub Origin/Host/role guard is the gate |
| web page -> content script | Page DOM is untrusted; the content script must not take configuration or commands from it |
| build tooling -> shipped extension | A build-time define could redirect the service worker if it accepted arbitrary hosts |
