Phase goal (ROADMAP, Phase 2): On a real page in Chrome, Blip reads the form's controls and fills them the way a person would, and only ever reports the value the page actually holds.

This plan builds everything the developer needs to drive and demonstrate the real extension without the voice UI: the server act path that turns REPL phrases into fill, select, check and focus requests and speaks the value read back from the DOM (A-01, roadmap criterion 3), the `--no-fake-extension` dev runner flag, a core-owned test-page server with the pages the manual checklist and automated tests rely on (D-11), and the `ext:chrome` launcher for the dedicated profile (D-10, A-08). It leads with a server tracer that fills one text field through the fake extension, then expands to the remaining ops and failure modes, then builds the test pages.

Purpose: plan 02-05's real-browser tests assert page-side state through the report endpoint and page contract defined here; plan 02-06's I1 check and manual checklist use the REPL phrases and the launcher.

Output: `executeUngated`, fake-brain phrases, `npm run dev -- --no-fake-extension`, `tools/test-pages`, `npm run ext:chrome`, `pages:serve`, `pages:build`.

Roadmap success criteria served: 3 (server half: reply reports the DOM value, truncated values reported truncated), 4 (the pages that trigger reveals, errors and route changes), 5 (REPL path to the extension).
