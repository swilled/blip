<objective>
Phase goal (ROADMAP, Phase 2): On a real page in Chrome, Blip reads the form's controls and fills them the way a person would, and only ever reports the value the page actually holds.

This plan is the deterministic, browser-free half of the lane. It makes the server keep its form model fresh when the page changes (PAGE-05, the server half of roadmap criterion 4) and writes the fail-closed classification rules that decide what every button, link and field is (PAGE-03, roadmap criterion 2). It leads with a server tracer: an extension-side `page.changed` produces a refreshed model and a `state` push to the voice client with no utterance, then hardens the refresher's concurrency and ordering semantics, then writes the pure classifiers with a table of adversarial cases.

Purpose: plan 02-03's content script imports the classifiers to set `kind` on every action; plan 02-04's server act path imports `fieldKindForFieldType` and calls the refresher after each act; plan 02-05's page-change detection is only useful because the server reacts to it here.

Output: `createRefresher`, the ordering-guarded `Session.applySnapshot`, `@blip/policy/classify`, and tests that fail when fail-closed behavior or single-flight semantics are removed.

Roadmap success criteria served: 2 (fail-closed kinds, rules half), 4 (model reflects a change within about 1 s, server half). Locked decisions: D-05, D-15, D-16 (server ordering), Phase 1 D-11. Amendments: A-05 (no server debounce, always re-snapshot after an act, re-snapshot on read-back/requirements intents older than about 2 s), A-06 (zod-free classify module with a parity test), F6 (server trusts RawElement.kind; it does not re-run classifyAction).

Shared files: none. `packages/protocol` is not touched. `apps/server/package.json` is not touched in this plan (the server does not import `@blip/policy` here); plan 02-04 declares that dependency when its act path first imports it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| page text and attributes -> classifier | Button text, hrefs and tags are attacker-controlled and decide whether Blip may click |
| extension -> server snapshots | A late or replayed snapshot could overwrite a newer model |
| page mutations -> server load | A hostile page can fire constant changes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-08 | Tampering | classifyAction fail-open | high | mitigate | Default result is submit; javascript: links, malformed or missing hrefs, empty text and unknown tags are gated; click-safe only by explicit allowlist or a same-origin link; table test includes junk and hostile rows |
| T-02-09 | Denial of service | Classifier regexes on hostile text | medium | mitigate | Linear word-boundary alternations only, text sliced to 500 characters before matching; 10,000-character timing test under 50 ms |
| T-02-10 | Tampering | Policy ungated list drifting from the protocol | medium | mitigate | Local ungated set with a parity test against isGatedKind for every ActionKind option and junk strings; source check that classify.ts has only type imports from the protocol |
