## Cross-phase integration

The read-only integration audit checked the supported launch path and its page, brain, reducer, executor, and result links. It found one handoff gap: the first-party voice UI sent `confirm.redeem` through the core Executor, but the DialogueRunner's own reducer did not receive the result. After a successful submit, the reducer could remain in `awaiting-confirm` and reject the next ordinary request.

That gap is fixed. `confirm.redeem` now checks the active grant and read-back IDs, then re-enters the DialogueRunner reducer and the same core GatePort. A refused early or mismatched UI confirmation clears its grant and UI redeeming state without submitting. The production Edge browser E2E verifies the first-party UI submits once and answers “what's here” normally afterward. Focused tests cover early-refusal invalidation and one-use dispatch. **Integration score: 1/1 canonical path verified.**

The only documented connected launch path is `npm run demo`; the dev REPL and legacy server entrypoints serve development paths and are not represented as equivalent I2/I3 flows.
